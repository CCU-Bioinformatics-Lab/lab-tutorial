為什麼重要

[[LongPhase-TO]] 是 tumor-only 支線的基礎。它在沒有配對正常樣本的情況下， 執行 LOH 偵測、候選 somatic 判定、phasing 與 purity 估計。

缺少正常樣本對照時，流程改以haplotype 與 graph 結構作為判定證據。本節說明這些結構。

概念與互動

第一步：以 clipping 界定事件邊界

要偵測染色體等級的 [[LOH]]，需先界定待分析的基因體區段。 LongPhase-TO 會檢查 [[soft clipping]] 的分布（M4 的 CIGAR S）：

  • 大量 read 在某處出現左端 clipping，可能對應 coverage 上升的轉折（up clipping）
  • 大量 read 在某處出現右端 clipping，可能對應 coverage 下降的轉折（down clipping）
  • 一組 up/down clipping 可提供 CNV 或 [[BFB]] 事件區間的候選邊界，仍需其他訊號驗證
{{svg:m13-clipping-interval | [wide] 三層。① clipping 與 coverage 的轉折可提供候選事件邊界：上升處常見「左端被剪」、下降處常見「右端被剪」，一組上下界定一個候選區間；此步驟不直接使用 variant calls。② 對每個區段計算雜合比例，比例偏低時標記為 LOH 候選；中間夾的小事件可能使連續 LOH 被切成數段。③ 排除小事件後重算，有助於估計連續區段的範圍。}}

實際訊號可能較分散 —— 有些事件是「緩升緩降」的，clipping 分布在一小段區域而非單一位置。 因此可用滑動視窗累積 clipping 訊號，再依峰值定位候選邊界。

第二步：以 heterozygosity ratio 找 LOH 候選

切好區段之後，統計每個區段裡 heterozygous 位點的比例。 比例低於預設門檻時可標記為 LOH 候選，並需結合 coverage、mapping 與其他 QC 判讀。

為什麼不用 coverage？

回到 M8 的 LOH 模擬器：copy-neutral LOH 的 coverage 可接近正常範圍。 因此單獨依 coverage 可能漏檢 copy-neutral LOH。

heterozygosity ratio 可對 copy-loss 與 copy-neutral LOH 提供訊號， 因為兩者都可能使原本的 het 位點減少；敏感度仍受 coverage、mapping 與門檻影響。

還有一個細節：LongPhase-TO 會排除區段內的小 CNV/BFB 事件再統計。 理由是一個大的染色體等級 LOH 裡面可能夾雜幾個小事件， 如果不排除，區段可能被切碎，原本連續的 LOH 可能被報成好幾段。 此設計旨在降低小事件對區段界定的干擾。

第三步：triplet graph 的三位點結構

沒有正常樣本時，如何判斷一個候選點是 somatic 還是 germline／artifact？ LongPhase-TO 會比較候選點與左右兩個 germline 位點的 allele 連結結構。

在 LongPhase-TO 的 triplet 模型中，三個位點比兩個位點具有更高的可分辨性。

{{svg:m13-triplet | [wide] 上半部用三個位點：在此局部演化模型中，符合 somatic 假設的候選可形成一條與來源路徑只差一個位置的新路徑；示意中的定序錯誤路徑則無法對應既有路徑。下半部只用兩個位點時，兩種示意情況呈現相同拓撲，僅憑這兩點無法區分。}}
  • 在此局部模型中，somatic 變異被視為從某一條既有 haplotype 衍生。 原本有兩條路徑（AGT 與 CGA），示例中的插入後路徑為第三條（C-GT-A）， 與 CGA 僅差一個候選位置，符合模型的衍生關係。
  • 在此示意中，定序錯誤路徑無法由任一既有路徑解釋；實際資料仍需結合 read 支持與品質指標。
  • 若只取兩個位點建圖，這兩種示意情況會產生相同拓撲， 因此僅憑兩點無法區分。

在此基礎上還可以再細分：兩條 germline haplotype 的側翼 allele 不一致時形成 12 種 high-confidence triplet；因 LOH 而只剩一條 germline haplotype 時形成 9 種 low-confidence triplet。 每個候選點周圍會建立多個 triplet graph，再依各類型計數與既定門檻決定是否保留。

第四步：解讀 GT:GT2:GT3

LongPhase-TO 把 somatic haplotype 寫在自訂的 VCF FORMAT 欄位， 分成三層。以下用解碼器示範此編碼：

{{widget:gt-decoder #gt {"value":"0|0:.|1:./."} | 從下拉選單逐一檢視七種常見組合。特別注意最後兩個LOH 區內的例子 —— 此時可使用 GT3，並呈現如 hp1-1-1 的階層標籤。}}
欄位描述的層次
GTgermline haplotype。有一側是 . 就代表這裡是 LOH
GT2LongPhase-TO 定義的 somatic haplotype。1|1 代表來源無法判定（hp3）
GT3LongPhase-TO 定義的 LOH 區內再分支，例如 hp1-1-1 與 hp1-1-2

第五步：估計 purity

此模型與 M12 的 GHIR 概念相近，另納入 LOH ratio。 LongPhase-TO 將 haplotype imbalance 的 Q1／Q3 與 LOH 比例作為多項式迴歸的輸入特徵， 估計模型定義的 purity。

真實證據

{{cli}} longphase-to phase \ -s SNP.vcf \ -b tumor.bam \ -r reference.fasta \ -t 8 \ -o phased_prefix \ --caller clairs_to_ssrs \ --pon-file PoN/gnomad.vcf.gz,PoN/dbsnp.vcf.gz \ --strict-pon-file PoN/1000g-pon.vcf.gz \ --loh {{/cli}}

注意：--caller 只接受 clairs_to_ss、clairs_to_ssrs、deepsomatic_to 三個值， 無效或省略時會回報錯誤（請以目前版本核對）。--pon-file 的參數值是逗號分隔的單一字串， 不是重複的旗標。--strict-pon-file 比 --pon-file 採更嚴格的匹配條件， 要求 position 與 ALT allele 都吻合。

如何檢視輸出

{{cli}} # purity 會寫入 VCF header grep '##tumor_purity' phased_prefix.vcf # 看 LongPhase-TO 加的 FILTER 標籤 grep -v '^##' phased_prefix.vcf | awk '{print $7}' | sort | uniq -c # LOH 區間 head phased_prefix_LOH.bed {{/cli}}

判讀練習

{{ask}}

你在輸出的 VCF 裡看到一列的 FORMAT 是 0|0:1|1:./.。

這代表什麼？這個位點的資訊完整嗎？

{{reveal}}

拆開來看：

  • GT = 0|0 —— 兩條 germline haplotype 都是 reference。 沒有 .，所以這裡不是 LOH 區。
  • GT2 = 1|1 —— 有 somatic 事件，但兩側都標成 ALT。 依定義這代表 somatic haplotype 無法判定，也就是 hp3。
  • GT3 = ./. —— 未使用第三層；非 LOH 情境通常不使用此欄位。

因此資訊不完整：依 LongPhase-TO 的 FORMAT 定義，工具將此列標示為 somatic 事件， 但無法判斷它源自 HP1 還是 HP2。

常見原因是該位點附近沒有足夠的 germline 錨點 —— 可能 read 太短， 也可能那一段本身 het 位點稀疏。

此設計在證據不足時保留未判定狀態，沒有指定單一來源。 這與 LongPhase-S 對 HP3 及並列候選的處理一致：保留不確定性，避免無依據的單一指派。

{{/ask}}

實作練習

執行完整流程

{{cli}} longphase-to phase \ -s tumor_snv.vcf \ -b tumor.bam \ -r reference.fasta \ -t 8 \ -o phased_prefix \ --caller clairs_to_ssrs \ --pon-file PoN/gnomad.vcf.gz,PoN/dbsnp.vcf.gz \ --strict-pon-file PoN/1000g-pon.vcf.gz \ --loh {{/cli}}

四項重要參數

  • --caller 在目前流程中應明確指定，只接受 clairs_to_ss、 clairs_to_ssrs、deepsomatic_to；無效或省略時會回報錯誤。
  • --pon-file 使用逗號分隔的單一字串，不是重複的旗標。
  • --strict-pon-file 要求位置與 ALT allele 都吻合才算命中，匹配條件較嚴格。
  • --loh 要自己加，否則不會輸出 LOH 區間。

檢視輸出

{{cli}} # purity 會寫入 VCF header（與配對版不同） grep '##tumor_purity' phased_prefix.vcf # 再校正後的 FILTER 分布 awk '!/^#/ {print $7}' phased_prefix.vcf | sort | uniq -c # LOH 區間，以及它們總共佔多少基因體 awk '{s+=$3-$2} END {print "LOH 總長度:", s/1e6, "Mb"}' phased_prefix_LOH.bed # 有 somatic 事件的位點（GT2 不是 ./.） bcftools query -f '%POS\t[%GT\t%GT2\t%GT3]\n' phased_prefix.vcf | \ awk '$3 != "./."' | head -20 {{/cli}}
