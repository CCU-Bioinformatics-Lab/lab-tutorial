為什麼重要

[[LongPhase]] 是本教材後續工具共用的基礎，處理的是一般（非腫瘤）樣本的 phasing。 開始分析腫瘤資料前，先掌握這個基本流程。

概念與互動

輸入與輸出

子命令輸入輸出
phasegermline SNP VCF ＋ BAM ＋ reference含以 | 表示相位的 GT 與 [[PS tag|PS]] 的 phased VCF
haplotag已 phase 的 VCF ＋ BAM ＋ reference每條 read 帶 [[HP tag|HP]] tag 的 BAM
modcall帶甲基化的 BAM ＋ reference甲基化的 VCF；是否可供後續 phase 請依目前版本文件確認

注意這個順序：先 call variant，再 phase，最後 haplotag。 LongPhase 本身不做 variant calling —— 它需要別人先給它 het 位點當錨點。

phase graph 的基本概念

{{svg:m11-phase-graph | [wide] 三個步驟。① 將可區分兩條染色體的位置表示為節點。② 若 read 同時跨過兩個節點，就建立一條邊；邊的粗細表示支持強度 —— allele 組合一致時較強、互相衝突時較弱、沒有 read 跨過時不建立邊。③ 依一致性選擇相位指派，各連通部分形成一個 phase block。}}

可將每個 heterozygous 位點表示為圖上的一個節點。兩個節點之間若有 read 同時跨過， 就建立一條邊；邊的權重代表支持強度：

  • 多條 read 支持 A–C 與 G–T 的 allele 組合 → 強邊，方向較明確
  • read 支持的 allele 組合互相衝突（有些支持 A–C、有些支持 A–T）→ 弱邊，可能有定序錯誤或比對問題
  • 完全沒有 read 跨過 → 沒有邊，[[phase block]] 在這裡斷開

Phasing 會依據 read 支持的 allele 組合，選擇加權一致性較高的指派。 各連通部分形成一個 phase set，VCF 用 PS 標示。

三種失敗模式

{{svg:m11-failure-modes | [wide] 三種失敗模式及其可觀測指標。① 分段破碎：檢查 phase set 的數量。② 方向對調：與 truth 比對時，錯誤從某點起系統性出現。③ 大量 read 無法指派：檢查 HP 標記率。}}
失敗原因徵兆
[[phase block]] 斷裂read 太短，或中間沒有 het 位點同一條染色體上出現很多不同的 PS 值
[[switch error]]某處證據太弱，兩條 haplotype 被對調與 truth 比對時，錯誤從某一點之後系統性地發生
大量 read 未標記[[LOH]]、低 coverage、mapping quality 太低haplotag 後很多 read 沒有 HP

第一項與第三項在腫瘤樣本上可能更明顯，因為 LOH 與 copy number 異常會減少可用的 phasing 錨點。 LongPhase-S 與 LongPhase-TO 都針對這些腫瘤資料情境提供額外處理。

真實證據

最小可跑範例

{{cli}} # 1. 準備輸入（見 M4） samtools faidx reference.fasta minimap2 --MD -ax map-ont -t 10 reference.fasta reads.fastq -o aln.sam samtools sort -@ 10 aln.sam -o aln.bam && samtools index aln.bam # 2. germline calling（Clair3 或 PEPPER-DeepVariant，見 M5） # 產生 SNP.vcf # 3. phasing longphase-s phase \ -s SNP.vcf \ -b aln.bam \ -r reference.fasta \ -t 8 \ -o phased \ --ont # 4. haplotagging longphase-s haplotag \ -r reference.fasta \ -s phased.vcf \ -b aln.bam \ -t 8 \ -o tagged {{/cli}}

如何驗證輸出

{{cli}} # 在已定相的 heterozygous records 檢查 | 與 PS grep -v '^##' phased.vcf | head -5 # BAM 裡應該有 HP tag samtools view tagged.bam | grep -o 'HP:i:[12]' | sort | uniq -c # 有多少 read 沒被標到？ samtools view -c tagged.bam samtools view tagged.bam | grep -c 'HP:i:' {{/cli}}

最後兩行的差可用來估算未標記的 read 數。請將差值除以總 read 數， 再依資料品質與分析目標判讀；比例偏高時，回到 M6 的排查清單。

常見參數注意事項

細節說明
--ont / --pbLongPhase-S 的 phase 需指定平台。LongPhase-TO 目前僅支援 ONT；即使接受平台旗標，也不會改變其處理方式。
-q 預設值不一致haplotag 是 1，estimate_purity 是 20；同一份資料可能因子命令不同而產生不同結果。
--sv-window部分版本的 help 與實際註冊選項不同，實際選項可能是 --svWindow；執行前請核對版本。
modcall 的 -b部分版本的 help 顯示 --bam-file，實際選項可能是 --methylbamfile；請以目前版本為準。

遇到不一致時的處理

以上差異是在特定版本觀察到的 help、文件與程式選項不一致。 請以目前版本的 src/phase/Phasing.cpp 中 longopts 表為準，並記錄版本。 使用新參數前，先檢索該表確認名稱。

判讀練習

{{ask}}

你在一條染色體上完成 phasing，發現輸出的 VCF 裡有 將近 200 個不同的 PS 值。

這正常嗎？該從哪裡查起？

{{reveal}}

數量偏高，建議檢查。在 read 長度與 heterozygous 位點密度足夠時，長讀通常可形成較大的 phase blocks；實際數量仍取決於資料品質與參數設定。

排查順序：

  1. 先看 read 長度分布。samtools stats 看平均與 N50。 如果 read 只有 2–3 kb，block 破碎可能是預期結果，不一定代表程式錯誤。
  2. 再看 het 位點密度。如果 VCF 裡的 het 位點本來就稀疏（例如樣本本身雜合度低， 或這條染色體有大段 [[LOH]]），可用錨點就會減少。
  3. 看斷點的位置分布。如果斷點集中在特定區段，那多半是該區段有問題 （LOH、重複序列、低 coverage）。如果均勻散布，那是全域性的 read 長度或參數問題。
  4. 檢查 -d（distance）參數。若目前版本預設為 300000，距離超過此值時就不嘗試連接。 如果資料 read 特別長，可依版本文件評估是否調大。

腫瘤樣本中，LOH 是造成這種現象的常見可能性之一：該區域的兩條染色體變得難以區分， 可用錨點可能大幅減少。腫瘤專用工具因此需要額外處理 LOH 區域，否則 phase blocks 可能變得零碎。

實作練習

執行最小流程

{{cli}} # 僅執行小區域測試，以縮短重複測試時間 REGION="chr20:1000000-2000000" longphase-s phase \ -s SNP.vcf \ -b aln.bam \ -r reference.fasta \ -t 8 \ -o phased \ --ont longphase-s haplotag \ -r reference.fasta \ -s phased.vcf \ -b aln.bam \ --region "${REGION}" \ -t 8 \ -o tagged {{/cli}}

保存參數設定

執行前請確認目前版本可接受的長選項，因為 help 訊息與實際接受的長選項 不一定一致：

{{cli}} # 確認目前版本接受的長選項 longphase-s phase --help # 如果 help 與實際行為不符，查閱原始碼裡的選項表 grep -A40 'static struct option' src/phase/Phasing.cpp {{/cli}}

目前版本的已知差異

  • 部分版本的 help 寫 --sv-window，實際註冊的是 --svWindow；請核對版本後再執行。
  • modcall 的 help 可能寫 --bam-file，實際選項可能是 --methylbamfile；請以版本為準。
  • -q 的預設值在不同子命令不一樣（haplotag 是 1、 純度估計是 20）。同一份資料用不同子命令會得到不同結果。

遇到不一致時，請以目前版本原始碼的選項表為準。
